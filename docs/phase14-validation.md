# 复活基础模块：规则与下落前外观

日期：2026-09-08。本文按批次记录复活迁移；下文早期记录保留当时边界，最新状态见末尾“棋盘与奖励贯通”。当前普通纵向复活已可用并实玩验证，混合机制和完整表现仍未全部完成。

## 原版依据

只读分析原项目 `assets/_script/GameSc.js` 的 `reviveTopFloorBalls`（约3143—3765行）、`captureRevivePreDropState`、`restoreRevivePreDropState` 及 `dropBallNode`。未修改原项目。

- 纵向优先回收最高的三颗普通触底水果，排除宿主及黑洞成员；不足三颗不追加回退配对。
- 完全没有普通回收对象时，选择最多两个符合条件的触底种子，各自找同类伙伴。两个种子互相排除；宿主、容器内成员和出现动画中的对象不能参与该回退。
- 横向每次消除后重新读取实例，最多尝试两次，不能提前静态规划两对。最高水果无伙伴时不跳过它。横向原脚本未排除出现动画标记，这与纵向回退不同。
- 同类伙伴优先最高触底对象，否则最低非触底对象。选择排序保持原遍历顺序的同高度优先级。
- 纵向搜索步长80像素，左右交替最多六格、向下40行；圆间距至少80像素且额外留5像素。搜索失败使用3200像素向下保底，随后整体抬升到最低-70像素；空等待区从-150像素开始。
- 黑洞容器抬升比例0.5；回收动画原版0.5秒 sineOut。当前只输出抬升数据，扁平黑洞实例与原版容器、子节点双层移动的等效应用还需接入验证。

## 代码边界

- `ReviveSelection`、`RevivePlacement` 为独立纯规则，不引用 cc、不控制 UI。
- `ReviveVisualState` 保存现有预制体子树的显隐、缩放、旋转、颜色、透明度，深复制值对象。恢复不改变坐标，不创建节点，不回滚关卡计数。
- `FruitItem.drop` 已接入下落前快照记录；外观恢复调用仍等待完整复活流程接入。
- `HiddenFruitView` 改为 onEnable 重新绑定、onDisable 解除监听，保证恢复已有花朵后再次触地仍可揭示。
- 新脚本及文件夹 meta 由 Creator MCP 刷新生成；没有手写序列化资产。
