# 第17阶段：黑洞复活路径与层级位移修正

## 源码依据与调整

原项目 GameSc.applyBlackholeFromCfgItem 将初始宿主 setParent 到黑洞容器；releaseBlackholeMembersAtWorldPos 也把补出成员放入容器。reviveTopFloorBalls 同时收集容器和其中的静态水果，各自应用 0.5 倍抬升；syncBlackholeWrappersToHostBalls 再保持水果世界位置同步容器。

目标项目采用扁平水果节点，因此宿主和驻留成员都应获得完整基准抬升。修正 BoardReviveFlow 原先只给宿主半量的问题，并把宿主也标为容器内部占位。尚未释放的成员是配置队列，不额外创建虚拟占位或 UI 节点。

## 实际试玩：纵向黑洞回退

配置 tools/fixtures/revive-vertical-blackhole-fallback.json，共10颗。

- 两个宿主配对后剩余8颗，徽标从3降为2。
- 依次释放每组两名成员，四颗不同水果落到底部触发失败。
- 开发广告完整观看后，执行黑洞成员的强制配对回退，剩余8变4、进度60%；实际看到粉色爱心与星星爆炸表现。
- 继续释放上方剩余伙伴，通关至剩余0、100%；预览 error 日志为空。
- 此时黑洞队列已耗尽，该用例不代表尚有黑洞时的普通回收抬升通过。

## 实际试玩：普通回收时保留黑洞

配置 tools/fixtures/revive-vertical-blackhole-mixed.json，共8颗；两组黑洞宿主分别是1、3，每组待出成员分别是2、4，下方普通水果为1、2、3、4。

- 点击四颗普通水果触发失败，黑洞徽标均保持2。
- 开发广告完成后回收三颗普通水果，剩余保持8，一颗普通水果留在槽内。
- 此布局未触发整体抬升，不能据此声明正抬升距离已经视觉验收。
- 点击宿主与对应回收水果，继续释放成员并配对，最终剩余0、100%，显示第1关完成。
- 本轮新预览页 error 日志为空。
