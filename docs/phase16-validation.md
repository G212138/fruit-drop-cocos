# 混合复活实玩与音乐缓存修复

日期：2026-09-08。使用 Creator 3.8.8 的 localhost:7457 预览，通过真实关卡编辑器导入 JSON 并点击试玩，没有修改正式45关数据或直接调用游戏内部方法。

## 横向、隐藏、冰层与爆炸

配置：tools/fixtures/revive-horizontal-mixed.json。八颗水果，下排四种各一颗，上排对应伙伴；一颗伙伴有两层冰，两颗水果隐藏。

1. 初始界面显示8颗、两层冰及隐藏花朵。逐个释放下排四颗不同水果，触发失败。
2. 点击复活并在开发广告面板选择完整观看，捕获到原 baozha 骨骼的粉色爱心与星形爆炸，出现在两对被消除水果的位置。
3. 剩余8→4、进度0%→50%。爆炸结束后消失，冰层两层清零，冰层表现消失。
4. 点击解冻后的水果及剩余同类伙伴，继续消除至0颗、100%，显示试玩完成。此时预览 error 日志为空。
5. 结算返回编辑器正常。之后进入正式游戏仍是原第2关，试玩未修改正式关卡进度。

此次已直接看到爆炸画面；没有录音或听感证据，不声明实际音量和音质验收通过。

## 连续进出发现的音频问题

第二次试玩时记录到一条 Invalid audio clip（21:45:33 UTC），不是把本轮描述为全程无错误。引擎 AudioSource 的 clip 同步与一次性播放都可能输出该错误。检查 XForge SoundManager.load 发现它优先返回 audioCache，页面资源包卸载后仍可能保留失效的音乐 AudioClip；原业务退出只 stopMusic，没有清理缓存。

SettingsController 改为在退出及退出后迟到的播放回调中，通过公开 stopMusic + release('audio/music', 'page-game-res') 清理播放器和音乐缓存，没有修改框架或引擎。

验证：test-settings-audio.cjs 与 test-settings-lifecycle.cjs 通过；TypeScript 无 assets 目录诊断。新建干净预览页，实际完成“正式第2关→首页→正式第2关”，第二次进入画面正常，error 日志为空。这个结果支持当前复现路径的修复，仍需更长时间及不同设备的音频生命周期回归。
