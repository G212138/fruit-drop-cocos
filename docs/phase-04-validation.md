# 隐藏水果阶段

## 实现与源码依据

- 原 GameSc.initFruitByLevelData 中 h=t 添加 flower，缩放为 0.9；原 flower 预制体设计尺寸为 117×117。
- 原 BallSc.onBeginContact 在首次地形接触时记录 hasTouchedFloor；仅动态刚体清除 flower，点击或补位本身不会揭示。
- 原 GameSc 消除流程清除配对双方 flower，不要求双方都已触底。隐藏状态不影响同类判断。
- 新 HiddenFruitRules 只负责揭示条件；HiddenFruitView 是独立遮罩组件及预制体；FruitSpawner 仅实例化遮罩；FruitItem 只发布首次地形接触和消除事件。
- 修正 FruitItem 首次接触监听解除函数与注册函数不一致的问题。
- 开放第五关：原配置 92 个水果，其中 3 个隐藏水果，编号依次为 21、24、4。第六关及后续仍未开放，不将未知机制当成普通水果。

## 已完成静态与纯规则验证

纯规则覆盖点击不揭示、首次静态接触不揭示、首次动态接触揭示、消除揭示、隐藏不改变匹配条件，以及第五关隐藏数量与类型。原配对、判负、移动、存档测试一并回归。

三十一个预制体引用检查通过；Creator 导入新增脚本和图片并生成 meta，所有序列化资产由编辑器保存。新增业务类型检查与框架原有严格类型报错分开记录。

## 验证方法与交付边界

第三、四关使用临时真实引擎回归：从可见水果选同类，通过既有点击请求事件释放，等待物理结果，未直接修改水果位置、消除计数或判负状态；不写玩家存档。该方法是操作策略测试，不等于关卡可解性证明。临时跳关与自动操作代码在交付前移除。

冰块、黑洞、横向模式、广告、复活和平台包仍未实现。没有伪造广告成功或发放奖励。

## 浏览器实际回归
- 第四关 126 个水果连续释放后剩余 102 个，正常触发失败弹窗；修复后本轮没有 Box2D 异常。第三关此前运行到剩余 58 个后失败。两者均未完成整关通关验证。
- 修复消除时刚体与碰撞体重复停用引起的碰撞代理异常：消除只停用刚体，节点销毁时统一释放碰撞体；同时清理该水果的补位动画和输入锁占用。结算冻结改为静态刚体。
- 第五关原始布局正确显示 92 个水果和问号花朵遮罩。另用两颗隐藏水果的临时布局验证真实触地揭示，未释放水果仍保持遮罩。此布局不代表第五关通关，交付前移除。
- 两颗隐藏水果测试布局已真实配对完成，并通过重新挑战确认遮罩恢复；未修改用户存档。
- 临时跳关、自动操作和测试布局已从交付源码移除。
