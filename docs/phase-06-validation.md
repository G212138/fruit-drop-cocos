# 黑洞运行机制验证

## 原版依据与实现

- GameSc.queueReleaseBlackholeMembersIfHost：当前宿主或仍在黑洞内的成员离开后，只安排一个下一成员；重复通知不能重复释放。
- releaseBlackholeMembersAtWorldPos：成员按 SequenceID 升序；延迟0.02秒，0.5秒 sineOut 放大到1.2倍，0.1秒 sineInOut 回到1倍。成员继续使用原始隐藏与冰层配置。
- 出现动画结束后关闭的碰撞需避让下落水果：中心距离小于双方估计半径和的0.6倍时等待；0.9倍范围内，线速度平方大于400或角速度大于10也等待；最多等待2秒。
- BlackHoleFlow 独立管理顺序、出现与保护；BlackHoleRules 维护数值和纯规则；BlackHoleView 只负责原图片和数量；FruitSpawner 复用普通水果工厂和事件绑定。不存在运行时代码创建 UI 节点。
- 迁移适配：新成员先创建为零缩放、禁用刚体的占位实例，让同帧纵向补位也能带动黑洞，0.02秒后才开始出现；这段延迟内不参与全场减冰。原版延迟回调后才创建节点。碰撞避让目前每帧检测，原版约每0.05秒检测一次；复杂高速混合场景仍需进一步对比。
- 黑洞底图置于水果后方，数量标记置于前方；清理时一并销毁重新排序的底图。最后一个水果出现后隐藏黑洞和数量标记。
- 原两张黑洞图片复制到 game/resources/textures/black-hole.png 与 black-hole-badge.png；尺寸70、37，数量底图位置(24.534,-20.877)、缩放0.8来自原预制体。当前数量使用系统字体，原字体尚待同步。

## 验证结果

- 通过编辑器导入四水果黑洞关卡：一颗宿主、一颗普通同类水果、两个相同成员。初始剩余4，标记3；宿主配对后剩余2、标记2；第一成员释放后最后成员补出并隐藏标记；全部配对后剩余0、进度100%，显示胜利结算。
- 返回编辑器恢复原始四水果和宿主的两名环形成员，新预览会话控制台无错误或警告。
- 修复编辑器 EditBox 与 Mask 位于同节点的重复渲染组件警告：由编辑器创建独立裁剪父节点。
- 规则测试覆盖原第15关完整数量及黑洞成员引用、出现曲线、避让距离和速度边界。这里读取第15关时只在测试输入中临时将序号设为1，没有修改原关卡资产，也不等同于第15关整关通关。
- 协调器测试覆盖顺序、重复释放、延迟、碰撞恢复、暂停、清理与重开；该测试模拟引擎边界，不代替实际物理试玩。
- 40个预制体引用验证通过；业务 assets 脚本类型检查没有新错误，完整 tsc 仍有既有框架扩展严格类型错误。
