# 冰层与编辑数据阶段验证

## 原版依据
- GameSc.markElimination 每消除两个水果调用 decrementAllFrozenBallsIce(1)。
- GameSc.dropBallNode 在 iceRemain > 0 时拒绝释放。
- setBallIceRemain：数字0.2秒放大至1.4倍后0.2秒恢复；清零时播 Spine 动画2与 Ice.mp3，2秒兜底清理。
- 原 ice2 预制体缩放0.45，标签字号80、y=-7.858，骨骼动画1为初始冰层。
- Editor.validateExportPayload 检查同类成对，以及不同黑洞组间距离大于50设计像素；黑洞总数量包含宿主，成员按SequenceID排序，导出使用宿主坐标。

## 实现
IceRules 管理纯数值，FruitItem 保存当前层数，GameBoard 在真实配对后通知 FruitSpawner 减层，IceFruitView 只控制独立预制体表现。新增完整三十种水果资源和碰撞轮廓。前十一关支持普通、隐藏、冰层；尚不开放横向及黑洞关卡。

LevelDocument 和 EditorDraft 为独立编辑数据层，支持45关的字段、成对/距离验证、黑洞宿主成员关系、导入失败保护、独立试玩快照。独立 PageEditor 页面和 EditorFruitMarker 预制体已接通增删拖拽、滚轮、删除键、导入导出及试玩返回；横向和黑洞试玩仍暂不开放。

## 实际验证
- 规则测试通过；原第六至十一关数量依次106/112/106/106/104/102，第十关冰层30/20/25/40。
- 浏览器使用临时六水果布局：冰层2时点击不下落；第一次真实配对后显示1；第二次配对后冰层清零；解冻水果正常释放并配对，最后进入胜利结算。没有新引擎错误。
- 临时测试未写玩家存档，测试布局与控制器临时代码已恢复。
- 三十九个预制体引用检查通过。骨骼/图片/音频通过 Creator 导入，预制体由编辑器序列化。
- 未宣称第六至十一关已整关通关，也未宣称全项目完成。框架扩展既有严格类型问题独立于业务脚本。

## 黑洞编辑与快捷键补齐
- 原 Editor.layoutBlackholeMembers：按 SequenceID 排列，半径60设计像素，至少6个槽位，成员缩放0.5。导入、增删成员、拖动宿主时同步环形布局，导出仍使用宿主坐标。
- 原 applyWheelDelta：小于5的增量乘50，随后乘0.2；纵轴范围[-2000,0]，横轴范围[0,1500]。试玩快照现包含两个轴。
- 补齐空格清空数字、数字键输入、回车添加和 Shift 隐藏；输入框获得焦点时不劫持键盘。
- 实际页面验证：四水果黑洞样例显示宿主及两名环形成员；拖动宿主成员跟随；Shift 标记隐藏；空格、数字2、回车添加水果；横向滚动及视口归零通过。
