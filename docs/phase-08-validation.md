# 关卡循环流程

原 GameSc.getLoopedLevelIndex 在累计关数不超过配置总数时使用对应布局；超过后使用 `2 + (累计关数 - 3) % (配置总数 - 2)`，即循环第三关至最后一关。只有一至两关配置时重复最后一关。

新增 loopedLevelIndex 和 loadCampaignLevel，正式 PageGame 加载入口通过它们选取原始配置，解析后仍将累计关数交给控制器、HUD 和存档。编辑器独立试玩不经过正式循环逻辑。

测试直接调用生产加载函数，覆盖1/2/3/45/46/47/88/89边界、第46关完整水果定义等于原第3关、第55关保留原第12关横向模式，以及独立存储中45→46→47和重新读取。坏输入和空配置仍报错，不静默改成第一关。没有修改玩家实际存档，也没有通过浏览器完整通关至第46关。

业务脚本类型检查无新增错误；项目整体 tsc 仍有既有框架扩展严格类型错误。45关逐关通关、引导、设置、道具、复活、奖励、主题和平台广告接口等剩余范围继续按 full-migration-status.md 推进。
